# 项目复盘归纳 —— 月报 Agent（Phase 2 笔记链路）踩坑与注意事项

> 用途：复习 / 面试前的速查。每条按「现象 → 根因 → 正确做法」组织，末尾给面试话术。
> 项目一句话：LangGraph + LangSmith + DeepSeek，自动拉 GitHub commit + 本地 Markdown 笔记，生成结构化月报。

---

## 0. 一句话核心认知（最值钱的一条）

> **AI 帮你"写"代码，但帮不了你"懂"和"审"。
> 是"AI 写错了你能不能一眼看出、为什么错、怎么改对"。**

正确的 AI 辅助工作流（四步，缺一不可）：

```
1. 写清楚 spec（设计契约，喂给 AI）
2. AI 生成草稿
3. 🔑 你逐条对照 spec 审查（不是"能跑就行"，是"符合契约吗"）
4. 你能讲出每一行"为什么这么写" + 跑通并人工核对数据
```

**本次踩坑**：第 3 步被跳过。AI 生成的代码用了 `os.walk`（spec 明确说用 `git ls-files`）、
用了 `stat.st_mtime`（spec 明确说用 `git log`）、自创了"方案B 整月 diff"（spec 定的是逐文件 git log）。
这三个违规，只要做了"对照 spec 审查"就会第一眼发现。

## 1. git 相关（本项目踩坑最多的区域）

### 1.1 中文文件名被静默丢弃（core.quotepath）⭐ 最容易踩

- **现象**：`git ls-files` 输出的中文文件名是 `"AI\345\255\246\344\271\240.md"`（八进制转义+加引号），
  拿这个串再去 `git log -1 -- <path>` 匹配不到 → 返回空 → 中文笔记被静默跳过，**不报错**。
- **根因**：git 默认 `core.quotepath=true`，把非 ASCII 路径转义成八进制。
- **正确做法**：所有 git 命令加 `-c core.quotepath=false`，让 git 输出原始 UTF-8 路径。

```python
subprocess.run(["git", "-c", "core.quotepath=false", "ls-files", "--", "*.md"], ...)
```

> 面试话术：*"Windows 上 git 默认把非 ASCII 文件名转义成八进制，导致路径匹配不到、文件静默丢失；
> 我统一加 `-c core.quotepath=false` 关掉这个行为。"*

### 1.2 pathspec 大小写敏感

- **现象**：`git log -1 -- "Linux基础.md"`（大写L）返回空，而实际文件名是 `linux基础.md`（小写）。
- **根因**：`core.ignorecase` 只管 index 比对，**不管 pathspec 匹配**，log 的路径匹配默认大小写敏感。
- **正确做法**：用 `git ls-files` 拿到的**原样路径**当 pathspec，不自己手拼路径字符串。

### 1.3 `git log -1 -- <file>` 空输出的两种含义

- **现象**：输出为空。
- **根因（两种，输出上无法区分）**：① 路径拼错/大小写不符；② 文件真的从未被提交。
- **正确做法**：空输出只能"排除该文件"，不能断定"它没产出过"。fail-safe：拿不准就丢，不污染数据。

### 1.4 为什么用 `git ls-files` 而不是 `os.walk`

- 路径与 commit 历史**严格一致**（避 1.2 的大小写坑）
- **天然排除未跟踪文件**（临时文件、密钥文件如 API_KEY.md 不会混进来）
- 自动跳过 `.gitignore` 排除的文件

### 1.5 为什么用 `git log` 而不是文件 `mtime`

- **现象/根因**：Obsidian 会自动保存，文件修改时间每天都在变，是"磁盘写入噪音"；
  git commit 时间戳才代表"有意识的内容产出"。
- **正确做法**：`git log -1 --format=%ai -- <file>` 取最后 commit 时间判断"本月是否动过"。

> 面试话术：*"我用 git 时间戳而不是文件 mtime 做过滤，因为 mtime 会被编辑器的自动保存污染，
> git 时间戳才反映真实的内容产出节奏。"*

## 2. LangGraph 与 State 设计

### 2.1 State 字段 key 必须与 TypedDict 严格对齐

- **现象**：key 不对齐**不报错，但数据静默丢失**（LangGraph 浅合并只认定义过的 key）。

### 2.2 浅合并语义

- 节点 `return` 的 dict **只覆盖列出的 key**，其余字段维持上一步的值不变。

### 2.3 fan-out / fan-in（并行汇合）

- 一个节点**只有等它所有上游边都完成后才会执行**。
- 本项目：`START → fetch_github_commits` 和 `START → scan_notes_in_time_range` 两条链并行，
  最后都在 `analyze_tech_points` 汇合。

### 2.4 字段溯源 / YAGNI ⭐ 设计铁律

- **每个字段必须能在上游找到来源**，填不上"数据来源"的字段就该删。
- 反面案例：`NoteFileInfo.diff_summary`（从 CommitInfo 复制粘贴来的，笔记没有 diff）、
  `NoteContent.topic`（topic 是 LLM 分析产物，parse 阶段根本没有）。
- YAGNI（You Aren't Gonna Need It）：只加"下游确实会消费"的字段，删字段比加字段更需要勇气。

### 2.5 命名语义

- 命名要反映**"数据是什么"**，不是"数据将来变成什么"。
- 反面案例：`notebooks_commits`（实际是文件扫描结果，不是 commit）、
  `analysis_notes_content`（实际是原始素材，不是分析产物）。
- 定稿名字：`note_files`（扫描元数据）/ `note_contents`（解析正文）。

## 3. LLM 接入

### 3.1 五步范式（面试要能背）

```
1. 结构化数据 → 文本           （_format_*_for_prompt）
2. 填 prompt 模板             （prompt.format(...)）
3. model.invoke(prompt)       （调 LLM）
4. json.loads 解析            （拿结构化结果）
5. 组装对象写回 state          （return {"字段": [...]}）
```

两个数据源接入 = 复制这 5 步，各写一个 `_format_xxx_for_prompt`，在同一个 prompt 里汇合。

### 3.2 token 成本控制 ⭐ 真实数据才能暴露

- **现象**：冒烟测试一跑，6 篇笔记拼出 **92,295 字符**的 prompt（AI学习.md 单篇就 41KB），
  会导致 token 爆炸、稀释重点、甚至超上下文窗口。
- **正确做法**：截断到 `MAX_CHARS_PER_NOTE = 4000`（与 Phase 1 对 commit diff 的 1200 字符截断同思路），
  截断后 24,022 字符。
- 后续可升级：分块（chunking）/ 先摘要再分析 / embedding 检索。

### 3.3 返回内容清理

- LLM 可能额外包一层 ``` ```json ... ``` ```，解析前先剥掉。

### 3.4 response.content 类型

- `response.content` 是 `str | list`，要 `isinstance` 判断后再 `.strip()`（Phase 1 踩过）。

## 4. subprocess / Python 基础

### 4.1 列表传参，不拼字符串 ⭐ 面试常考

- **根因**：拼字符串等于把解析权交给 shell → 空格/中文文件名被拆断 + 注入漏洞。
- **正确做法**：`subprocess.run(["git", "-C", dir, "log", ...], capture_output=True, text=True)`。
  操作系统负责分词，文件名带空格（如 `Vibe Coding流程.md`）也安全。

### 4.2 编码防御

- `encoding="utf-8"` 读中文输出，`errors="replace"` 兜底（避免个别坏字节让整个进程崩）。
- 读笔记文件用 `encoding="utf-8"`（Obsidian 默认 UTF-8）。

### 4.3 dict 字面量用 `:` 不是 `=`

- 反面案例：`{"time_range" = ""}` → SyntaxError。函数参数才用 `=`，字典用 `:`。

### 4.4 环境变量名拼写

- 反面案例：`os.environ.get("DEEPSEEK_KEY")` 应为 `DEEPSEEK_API_KEY`，拼错 → 拿到 None，静默失败。

### 4.5 open() 目录会报错

- 反面案例：`output_path = "./docs"`（目录），`open(dir, "w")` → `IsADirectoryError`。
- 正确：`output_path` 必须是**文件路径**，如 `docs/report_2026-08-25.md`。

### 4.6 报错要定性

- `AttributeError: module 'langgraph' has no attribute '__version__'` 不是环境坏了，
  是"我的检查代码写错了"（langgraph 本就不暴露 `__version__`）。别被第一行报错吓住。

## 5. 设计原则（可复用到任何项目）

| 原则 | 含义 | 本项目体现 |
| -- | -- | -- |
| 职责单一 | 一个节点只做一件事 | scan（元数据）与 parse（读内容）拆两个节点 |
| fail-safe | 单个失败不中断整条链 | 读文件失败打印警告并跳过 |
| 渐进式交付 | 先跑通主链路，再扩展 | .md 完整实现，.pdf/.docx 走占位分支 |
| 契约一致性 | 代码与设计文档一致，改设计先改文档 | 换"方案B"前必须先沟通 |

## 6. 验证方法

1. **先命令行、后代码**：先手动 `git log -1 --format=%ai -- <file>` 验证命令行为，再写代码调用。
2. **冒烟测试**：只测新链路、不调 LLM/API、不花钱（如只跑 `scan_notes_in_time_range` + `parse_md_files`）。
3. **用真实数据跑**：92K token 爆炸就是拿真实笔记一跑才暴露的，假数据发现不了。
4. **图编译检查**：`app.get_graph()` 打印节点/边，确认接线（不调 API 就能做）。
