## 项目一句话描述

### 已踩坑并修复的问题（不要重复踩）

**Phase 1：**
- State字段key必须与TypedDict定义严格对齐，不对齐不报错但数据丢失
- `REPO`变量只填仓库名（如`train_llm`），不填完整git URL
- GitHub API 404可能是路径错，也可能是权限问题，两者都返回404，靠换正确路径反向验证
- LLM的`response.content`类型是`str | list`，已加isinstance判断
- merge commit的diff在GitHub API里等于"累积所有分支差异"，会与相邻commit重复，必须过滤
- `_is_low_info_message`返回`True`时**跳过不拉**（不是去拉），方向不能搞反

**Phase 2（详细复盘见 `docs/项目复盘归纳.md`）：**
- 中文文件名被 git 转义（`core.quotepath`）→ 加 `-c core.quotepath=false`
- pathspec 大小写敏感（`Linux基础.md` ≠ `linux基础.md`）→ 用 `git ls-files` 输出的原样路径
- 仓库转私有后 GitHub API 返回 **404（不是403）**：GitHub 故意不泄露仓库存在性；fine-grained token 需显式授权目标仓库 + Contents: Read
- **fork 方案已搁置**：fork 是"快照"不自动同步，且 commit 作者保留原作者，`author=新账号` 会把历史 commit 全滤掉（`github_username` 同时驱动 owner 和 author，语义不同要分开考虑）
- 笔记全量塞 prompt 会 token 爆炸 → 截断到 `MAX_CHARS_PER_NOTE`
- 环境变量名拼写错误（`DEEPSEEK_KEY` → `DEEPSEEK_API_KEY`）会静默拿到 None
- `output_path` 必须指向文件而非目录（`open(目录)` 会 IsADirectoryError）
